# 检索质量测评报告

> 所有数字均为本机实测，问题集、语料清单与脚本随仓库提供，可复现。无估算，无外推。

## 1. 目的

回答三个问题：

1. 混合检索（BM25 + 向量 + RRF + Multi-Query + 重排）相比单路检索，提升多少？
2. 重排用本地 cross-encoder 还是再调一次大模型？
3. 资料里没有答案时，检索分数能不能识别出来？

## 2. 测评设置

| 项 | 值 |
| --- | --- |
| 语料 | 20 篇 arXiv 论文，1436 个分块（每篇都做过首页关键词校验） |
| 问题集 | 80 题：每篇 4 题，术语型 40 + 口语型 40 |
| 命中判定 | **片段级**：前 3 个检索结果里，任一分块包含答案原文才算命中 |
| 负样本 | 10 题语料内无答案的问题，只用于检验重排分数的可分性 |
| 分块 | 向量与 BM25 共用 `split_chunks()`：480 字、重叠 60 字，每块带 `chunk_id` |
| Embedding | BAAI/bge-small-zh-v1.5（本地） |
| 多查询改写 | DeepSeek，temperature 0.2 |
| 重排 A | `BAAI/bge-reranker-v2-m3` cross-encoder，精排 RRF 前 12 个候选，每块看 1200 字 |
| 重排 B | LLM listwise，同样 12 个候选，每块只看 150 字 |

题目由 `scripts/gen_eval_questions.py` 从分块生成：每块出术语/口语各一题，
答案必须是原文中逐字出现的片段，题目不能直接包含答案，答案不能是跨 3 篇以上文档的通用短语。
生成后逐题校验「答案确实在标注分块内」，80/80 通过。

## 3. 结果

| 模式 | top-3 命中率 | 术语型 | 口语型 | p50 延迟 |
| --- | --- | --- | --- | --- |
| 向量单路 | 22.5% | 35.0% | 10.0% | 9ms |
| BM25 单路 | 38.8% | 75.0% | 2.5% | 4ms |
| 混合 RRF | 42.5% | 72.5% | 12.5% | 15ms |
| **混合全开（CE）** | **68.8%** | **92.5%** | **45.0%** | 4.7s |

固定同一批候选、排除改写波动后，两个重排器的对比：

| 重排器 | top-3 命中 | 术语型 | 口语型 | 单题重排耗时 |
| --- | --- | --- | --- | --- |
| **cross-encoder** | **51/80（63.8%）** | 37/40 | 14/40 | 2.2s |
| LLM listwise | 38/80（47.5%） | 28/40 | 10/40 | 7.7s |

负样本（10 题无答案）用 CE 最高分做区分，AUC **0.964**；
阈值取 0.0026 时，语料内问题（80 题）保留 95%，领域外问题拒绝 90%。
注意这组数据说明的是"分数能区分问题是否属于语料主题"，不等于"答案一定在 top-3 里"；
数值以 `docs/negative-check.json` 为准（语料内问题 top1 分数中位数 0.764，负样本 0.001）。

## 4. 结论

1. **片段级判定比文档级严格得多**：同一批语料，文档级全开能到 90% 以上，
   但"正确文档进 top-3"不等于"检索到的片段里有答案"。改成答案原文包含后，
   全开掉到 68.8%，这才是用户真正能拿到答案的概率。
2. **术语型已经够用，口语型仍是短板**：全开模式术语型 92.5%，口语型只有 45%。
   口语问题不含专业词，BM25 几乎失效（2.5%），靠的是查询改写把大白话转成可检索的表达，
   但中文口语到英文论文的跨语言改写仍不稳定。
3. **cross-encoder 明显强于 LLM listwise**：同一批候选上 63.8% 对 47.5%，
   术语型差距最大（37/40 对 28/40）。原因是 LLM 只能看到每块 150 字，
   判断不了这一块里是否真的有答案；cross-encoder 能读 1200 字，直接给相关性打分。
   同时 CE 单题 2.2s、不产生 API 费用，LLM 7.7s 且计费。
4. **精排候选数不需要多**：CE 只看 RRF 前 12 个，扩到 40 个命中率没有提升，
   耗时从约 2s 涨到约 10s。
5. **延迟**：全开模式 p50 4.7s，主要花在多查询改写；默认产品路径混合 RRF 是 15ms，
   深度检索才开全开。
6. **负样本可分**：AUC 0.964 说明 CE 分数能区分"问题是否属于语料主题"。
   如果以后要做拒答，0.0026 这个量级可以作为起点；但它区分不了"主题对、只是这段没答案"，
   真正的拒答还需要结合生成阶段。产品目前没有拒答逻辑，这组数据只作阈值参考。

## 6. 远程 embedding / rerank 对比（千问 MaaS）

同一套 80 题、同一份语料，只换向量化与重排：

| 配置 | 向量单路 | RRF | 全开 | 术语 | 口语 | 全开 p50 |
| --- | --- | --- | --- | --- | --- | --- |
| 本地 `bge-small-zh-v1.5` + 本地 `bge-reranker-v2-m3` | 22.5% | 42.5% | 68.8% | 92.5% | 45.0% | 4.7s |
| 千问 `qwen3.7-text-embedding-flash` + `qwen3.7-text-rerank` | **60.0%** | **62.5%** | **75.0%** | **97.5%** | **52.5%** | 3.4s |

负样本可分性：本地组合 AUC 0.964；千问组合 AUC 0.996，阈值 0.3567 时
语料内问题保留 97.5%、领域外问题拒绝 100%。

结论：

1. **提升主要来自跨语言向量化**：向量单路 22.5% → 60.0%。中文问题、英文论文，
   原来的 `bge-small-zh` 是纯中文模型，跨语言检索本来就是短板。
   同一对"联邦学习 / federated learning"，本地模型余弦相似度 0.60，
   千问 embedding 是 0.90（无关文本对照分别为 0.28 / 0.39）。
2. **全开模式只涨 6.2 个百分点**：因为改写和重排已经补上了一部分跨语言差距，
   向量路变强之后，瓶颈换成了口语提问本身。
3. **远程重排分数更干净**：AUC 0.996 对 0.964，且单题重排约 0.5s，比本地 CPU 的 2.2s 快。
4. **默认仍是本地模型**：API 需要 Key 和网络，不能作为开箱默认；设置页可以在
   「向量索引」与「检索重排」两处切换，远程接口失败会自动退回本地模型。

## 7. 复现

```bash
# 1. 下载并校验语料（20 篇，逐篇核对首页关键词）
python -m scripts.fetch_eval_corpus --out ~/.xueyu_eval_docs

# 2. 建干净的评测库并建索引
python -m scripts.fetch_eval_corpus --out ~/.xueyu_eval_docs \
    --ingest --data ~/.xueyu_eval_clean

# 3. 从分块生成 80 题（固定采样种子）
XUEYU_DATA=~/.xueyu_eval_clean python -m scripts.gen_eval_questions

# 4. 配置 research 模型后跑四模式 + 负样本
XUEYU_DATA=~/.xueyu_eval_clean python -m scripts.eval_retrieval

# 5. 固定候选池，单独比较 CE 与 LLM 重排
XUEYU_DATA=~/.xueyu_eval_clean python -m scripts.eval_rerank --ce-limits 12
```

远程配置在设置页填写，或者直接写进评测库的设置表（`embedding` / `rerank`），
然后用同一个脚本跑：`XUEYU_DATA=<评测库> python -m scripts.eval_retrieval`。

评测脚本会自检：未配置模型直接报错退出；任何一题改写或重排失败也会报错退出，
避免把降级成纯 RRF 的数据当成全开模式的结果。

## 8. 已知局限

- 题目由模型从分块生成，部分口语题偏笼统。抽查 12 道漏检题，约一半属于这类提问
  （如"把模型做得更大，效果会怎样？"），对检索难度的估计可能偏高。
- 语料是 20 篇英文 AI 论文、提问是中文，只覆盖"中文问英文文档"一个方向。
- 负样本只有 10 题，阈值结论只能当方向参考。
- 全开模式包含一次随机改写，单次运行之间会波动，表格里是其中一次的真实结果。
- 远程配置的数字依赖具体服务商与模型版本，换模型需要重测。
