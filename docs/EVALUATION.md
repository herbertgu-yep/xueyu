# 检索质量测评报告

> 所有数字均为本机实测，问题集、语料清单与脚本随仓库提供，可复现。无估算，无外推。

## 1. 目的

回答四个问题：

1. 混合检索（BM25 + 向量 + RRF + Multi-Query + 重排）相比单路检索，提升多少？
2. 多查询场景下，RRF 应该怎么融合才不丢排名信息？
3. 中文口语提问检索英文论文，查询改写要怎么做？
4. 重排后的相邻块扩展值不值得做？

## 2. 当前链路

| 环节 | 做法 |
| --- | --- |
| 切块 | `split_chunks()`：480 字、重叠 60 字，向量与 BM25 共用同一套边界 |
| 向量化 | 千问 `qwen3.7-text-embedding-flash`（1024 维，DashScope 原生协议） |
| 召回 | 向量 + BM25 双路，每路独立排名 |
| 融合 | 每个查询内部先做双路 RRF，再跨查询加权融合（原查询 1.0，改写 0.7） |
| 改写 | 中文同义改写 + 英文术语 + 英文检索式，原问题始终保留 |
| 重排 | 千问 `qwen3.7-text-rerank`，精排 RRF 前 12 个候选 |
| 上下文 | 前 3 个结果直接交给生成，不做相邻块扩展（实测收益见 §5） |

## 3. 测评设置

| 项 | 值 |
| --- | --- |
| 语料 | 20 篇 arXiv 论文，1396 个分块（每篇都做过首页关键词校验） |
| 问题集 | 80 题：每篇 4 题，术语型 40 + 口语型 40 |
| 命中判定 | **片段级**：前 3 个检索结果里，任一分块包含答案原文才算命中 |
| 负样本 | 10 题语料内无答案的问题，用于检验重排分数的可分性 |
| 重排候选 | RRF 前 12 个，每块看 1200 字 |

题目由 `scripts/gen_eval_questions.py` 从分块生成：每块出术语/口语各一题，
答案必须是原文中逐字出现的片段，题目不能直接包含答案，答案不能是跨 3 篇以上文档的通用短语。
生成后逐题校验「答案确实在标注分块内」，80/80 通过。

## 4. 结果

| 模式 | top-3 命中率 | 术语型 | 口语型 | p50 延迟 |
| --- | --- | --- | --- | --- |
| 向量单路 | 55.0% | 75.0% | 35.0% | 299ms |
| BM25 单路 | 38.8% | 75.0% | 2.5% | 4ms |
| 混合 RRF | 62.5% | 90.0% | 35.0% | 330ms |
| **混合全开（改写 + 重排）** | **82.5%** | **95.0%** | **70.0%** | 3.4s |

负样本用重排最高分区分「问题是否属于语料主题」：AUC 1.000，
阈值 0.4377 时语料内问题全部保留、领域外问题全部拒绝（10 题样本，仅作方向参考）。

## 5. 这一轮修了什么

### 5.1 切块口径不一致，导致 RRF 的跨路命中失效

向量索引用的是带 metadata 的 `SentenceSplitter`，BM25 用的是不带 metadata 的
`split_chunks()`。metadata 参与切分时边界会变，同一篇论文两边的分块数对不上
（如 `rag-lewis-2020` 索引 48 块、BM25 47 块；全语料 1436 vs 1396）。
于是向量返回的 `48:3` 和 BM25 返回的 `48:3` 根本不是同一段文字，
RRF 的「同一块被两路同时命中」几乎从未发生。

修复：`index_document` 直接复用 `split_chunks()`，再用 `TextNode` 挂 metadata 和
`chunk_id`；同时把 `doc_id/title/chunk_id` 排除出向量化文本，避免标题泄漏进检索。
BM25 缓存签名也补上了每篇文档的长度与索引时间，防止「内容变了但总长度没变」时命中旧缓存。

代价是向量单路从 60.0% 掉到 55.0%（标题不再参与向量化），但全开反而涨了，说明对齐带来的收益更大。

### 5.2 多查询融合丢失排名信息

原来多个查询的向量结果按 `chunk_id` 去重、只保留最高分，BM25 只保留首次出现，
最后把两个字典的 `values()` 交给 RRF——字典插入顺序不是真实排名，一个块被多个查询命中的贡献也被丢掉。

修复：每个查询内部先做向量 + BM25 的 RRF，再跨查询做加权 RRF；原查询权重 1.0，
改写查询 0.7，避免改写跑偏时把原问题挤下去。一个块被多个查询同时召回时分数自然叠加。

### 5.3 查询改写没有针对跨语言场景

原提示词只要求「不同视角、同义词」，但这里的真实场景是中文口语问英文论文。
现在固定生成三类：中文同义改写、英文术语/缩写、贴近论文表达的英文检索式，
并做规范化去重、始终保留原问题。

### 5.4 三项改动的实测拆解

| 阶段 | 全开 | 术语 | 口语 |
| --- | --- | --- | --- |
| 旧融合 + 旧改写 | 75.0% | 97.5% | 52.5% |
| + 逐查询 RRF + 跨语言改写 | 81.2% | 97.5% | 65.0% |
| + 切块对齐 + 排除标题向量化 | **82.5%** | **95.0%** | **70.0%** |

口语型合计从 52.5% 提到 70.0%，是这轮的主要收益；术语型掉了一题，属于波动。

## 6. 相邻块扩展值不值得做

对前 3 个结果，把命中块的前后各 1 块也算进上下文，命中率从 82.5% 提到 **83.8%（+1.3 个百分点）**。
代价是生成阶段的上下文大约翻三倍。结论：暂不做，收益不匹配成本；如果以后要做，
只对前 1-2 个结果扩展，而不是全部。

## 7. 低置信度拒答

重排阈值按模型保存在 `rerank.thresholds` 里，用 `scripts/calibrate_rerank.py` 校准：

```bash
XUEYU_DATA=<评测库> python -m scripts.calibrate_rerank --save
```

当前千问重排模型的结果：正样本 80 题最高分中位 0.951，负样本 10 题中位 0.178；
AUC 0.999，阈值 0.3096 时有答案保留 98.8%、无答案拒绝 100%。

产品里的闭环：检索结果带 `low_confidence` 标记；研究 Agent 会把低于阈值的片段
挡在信源之外，全部低于阈值时记录「检索置信度不足」并跳过，不再拿弱相关内容生成。
注意这组阈值和评测用的是同一批 80+10 题，只能算方向性校准，
上线前应当用另一批独立问题重测。

## 8. 复现

```bash
# 1. 下载并校验语料（20 篇，逐篇核对首页关键词）
python -m scripts.fetch_eval_corpus --out ~/.xueyu_eval_docs

# 2. 建干净的评测库并建索引（在设置里配置 embedding）
python -m scripts.fetch_eval_corpus --out ~/.xueyu_eval_docs \
    --ingest --data ~/.xueyu_eval_clean

# 3. 从分块生成 80 题（固定采样种子）
XUEYU_DATA=~/.xueyu_eval_clean python -m scripts.gen_eval_questions

# 4. 配置 research 模型、embedding 与 rerank 后跑四模式 + 负样本
XUEYU_DATA=~/.xueyu_eval_clean python -m scripts.eval_retrieval
```

评测脚本会自检：未配置模型直接退出；任何一题的改写、远程重排或向量路失败/降级，
也会直接报错退出，避免把「退回本地模型」或「退化成纯 BM25」的数据当成全链路结果。

## 9. 已知局限

- 题目由模型从分块生成，部分口语题偏笼统。抽查 12 道漏检题，约一半属于这类提问
  （如"把模型做得更大，效果会怎样？"），对检索难度的估计可能偏高。
- 语料是 20 篇英文 AI 论文、提问是中文，只覆盖「中文问英文文档」一个方向。
- 负样本只有 10 题，AUC 1.000 只能说明当前样本上可分，不能当成线上阈值。
- 全开模式包含一次随机改写，单次运行之间会波动，表格里是其中一次的真实结果。
- 远程模型的数字依赖具体服务商与模型版本，换模型需要重测。
